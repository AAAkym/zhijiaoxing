## 0. 一句话目标

让每一份生成的学习资源都能回答"**我为什么是给你的**"：

- **学生**点开一份资源，能看到：依据了哪几条画像证据、由哪几道错题推导而来、对应知识图谱哪个知识点、接下来该学什么、质量评分是多少。
- **老师**点开一个班，能看到：这个班分成哪几种学习类型、各多少人、每一组的共同薄弱点是什么、该给这一组补什么。

### 3.2 **诚实性硬规则（最重要的一条）**

当前系统里有些结论确实缺证据。**缺证据时必须显式标注，禁止编造。**

- 复用 `_dimension_details()` 已有的兜底文案：`"当前证据不足，建议通过画像对话或更多学习活动补充数据"`。
- 若某维度 `confidence < 60`，UI 必须展示"低可信"标记，不得展示为确定结论。
- 若拿不到错题明细（只有聚合计数），`mistake_evidence` 返回空数组并在 `gaps` 中登记 `missing_mistake_detail`，**不要用聚合数字伪造错题条目**。
- `_check_difficulty_alignment()` 的 `75` 是占位值。要么实现真实计算，要么在 `gaps` 中登记 `difficulty_alignment_is_placeholder`。**不允许把它当成真实结果展示。**

> 这条规则是本任务的第一验收项。一个会自曝短板的依据链，胜过一个看起来很完整但会撒谎的依据链。

### 3.4 分组规则（第一版：确定性规则，不用模型）

**不要引入 sklearn / numpy / 任何新依赖。** 第一版用可解释的规则分组：

1. 候选维度：`cognitive_style`、`goal_orientation`、`learning_pace`。
2. 主标签 = `cognitive_style` 取值（`visual` / `auditory` / `kinesthetic` / `reading` / `mixed`）。
3. 次标签 = 该生 `top_knowledge_points` 中**频次最高**的薄弱知识点（跨班聚合后取班级层面的共性项）。
4. 第三标签 = `goal_orientation` 取值。
5. `learning_type` = 上述三个 `display_value` 用 `" · "` 连接。
6. **证据不足者进入 `ungrouped_students`**，判据：`completeness_score < 40` 或 `confidence_score < 50`。禁止把证据不足的学生硬塞进某一组。
7. 少于 2 人的组并入 `mixed` 组，并在 `defining_features` 中标注合并原因。

若确实需要聚类算法，**必须先提 ADR**（涉及新依赖），得到批准后再做。

### 5.2 复用而非重写

- 已有 `GenerationCausalChain.jsx`：保留，用于"生成过程"视角。`ResourceBasisPanel` 是"这份资源"视角。两者**数据同源**（都来自 `generation_explanation` + `resource_basis`），不要产生两套互相矛盾的说法。

## 9. 验收标准（逐条自检，缺一不可）

**学生侧**

- [ ] 点开任意一份资源，能看到**至少一条**有出处、有可信度的画像证据。
- [ ] 能看到推导该资源的**具体错题**（若确实没有，明确显示"未关联到具体错题"，不得留空）。
- [ ] 能看到对应的**知识点 + 章节**，并能**跳转到知识图谱**。
- [ ] 能看到**"接下来学什么"**，且内容与 `PersonalizedLearningCycle.next_strategy` 一致。
- [ ] 能看到**质量评分**（四维 + 综合）。
- [ ] `media` / `ppt` 不显示引用覆盖率。
- [ ] 依据面板加载失败时，资源正文仍可正常打开。

**教师侧**

- [ ] 点开一个班，看到**分组结果 + 每组人数**。
- [ ] 每组能看到**共同薄弱点**（含覆盖人数与平均掌握度）。
- [ ] 每组能看到**可执行的补救建议**，并能一键发起该组生成。
- [ ] 证据不足的学生单独列出，**原因可见**，未被硬塞进任何一组。

**工程侧**

- [ ] 沿用现有范本文件的分层、命名、异常处理风格，未自创风格。
- [ ] 未引入新第三方依赖；如引入，已先提 ADR 并获批准。
- [ ] 未修改数据库 schema；如修改，已先提 ADR 并获批准。
- [ ] 未破坏任何既有 API 响应字段。
- [ ] 越权检查到位（班级级接口 403、学生只能看自己的依据）。
- [ ] `pytest` 与 `pnpm test` 全绿。
- [ ] 新增前端组件满足 a11y 要求（ARIA + 键盘 + 非纯颜色表达）。

## 10. 明确禁止事项

1. **禁止编造证据。** 缺数据就说缺数据。这是本任务的第一红线。
2. **禁止重写** `profile_explainability_service.py` 的纯函数契约（不得在其中读写数据库）。
3. **禁止另造**"下一步学习"逻辑，必须复用 `learning_cycle_agents.py`。
4. **禁止另造**质量评分逻辑，必须复用 `_assess_content_quality` 与 `ContentQualityPanel`。
5. **禁止把硬编码的 `75`（`_check_difficulty_alignment`）当作真实评分展示。**
6. **禁止引入** sklearn / numpy / 聚类库等新依赖（除非 ADR 获批）。
7. **禁止新建** `CLAUDE.md` / `AGENTS.md` / `.cursorrules` 等行为准则文件，也不得修改既有 `CLAUDE.md` 与 `.claude/skills/`。
8. **禁止使用占位符**输出（`// ...`、`// 其余不变`）；超长文件分批输出连续完整代码块并标注"待续"。
9. **禁止在学生端泄露**其他学生的依据数据；所有依据查询必须按当前会话 `user_id` 过滤。
10. **禁止**在日志、错误信息或提交差异中输出任何疑似密钥 / Token / 凭据；发现即遮蔽并警告。
