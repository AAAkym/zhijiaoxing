### 1.4 🚨 一个会骗你的陷阱（上一轮踩过，你必须知道）

`backend/src/main.py:1059-1072` 有一个**通配 SPA 兜底路由**：

```python
@app.route('/', defaults={'path': ''})
@app.route('/<path:path>')
def serve(path):
    ...
    return send_from_directory(static_folder_path, 'index.html')
```

**它把所有未匹配路径（包括 `/api/*`）返回 `index.html`，且状态码是 `200`。**

后果：**"路由不存在"与"功能正常"在 HTTP 层面无法区分。**

由此推出三条你必须遵守的验证纪律：

1. **验证任何后端接口，必须检查 `Content-Type` 是否为 `application/json`。** 返回 `text/html` 就等于"路由不存在"，哪怕状态码是 200。
2. **新增路由后必须重启 Flask**，然后用 `app.url_map` 或实际 HTTP 请求确认注册成功。写了代码 ≠ 服务加载了代码。
3. **禁止仅凭"页面没报错"判定功能正常**——前端有降级兜底，永远不报错。

**已知教训**：本仓库最近一次事故就是"新路由写了但后端没重启"，导致新功能全部静默失效，而界面只显示友好降级文案。
