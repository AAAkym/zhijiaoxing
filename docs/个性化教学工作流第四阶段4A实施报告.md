# 个性化教学工作流第四阶段 4A 实施报告

更新时间：2026-07-23

## 一、本批结论

第四阶段第一批 4A 已完成，第四阶段整体尚未完成。

本批解决的是“任务多了以后怎样找到和管理”，没有新增数据库表、没有修改数据库字段、没有执行迁移，也没有把测试连接到 `backend/instance/dev.db`。

```text
教师发布很多任务
→ 按关键词、状态、截止状态查找
→ 选择本页任务
→ 批量暂停或恢复
→ 后端逐条检查是否属于当前教师

学生收到很多任务
→ 按关键词、任务状态、截止状态筛选
→ 分页查看
→ 看清无截止、进行中、即将截止、逾期或已完成
```

## 二、改了什么

### 1. 截止状态

接口根据现有 `due_at`、完成时间和任务状态实时计算：

- `none`：没有截止时间。
- `active`：距离截止超过 24 小时。
- `due_soon`：24 小时内截止。
- `overdue`：已超过截止时间，但这不等于任务失败。
- `completed`：任务已经完成。

这是读取时计算，不写入新的截止状态记录，因此不会为了查看页面而修改数据库。

### 2. 教师任务运营

教师端新增独立“任务运营”区域。当前页面直接提供：

- 任务、学生姓名和任务编号搜索。
- 任务状态和截止状态筛选。
- 服务端分页，默认每页 10 条，接口最多每页 100 条。
- 本页全选、单项选择、批量暂停和批量恢复。
- 显示任务总数、学生、班级、课程、进度和截止状态。

后端接口还支持课程、班级、学生和发布时间筛选，但 4A 页面暂未增加这四组控件，避免在没有真实任务量反馈前把操作区堆得过密。

后端会逐条按当前登录教师校验所有权。通过修改请求参数加入其他教师的任务时，该任务只会返回“跳过”，不会被操作。

### 3. 学生任务中心

学生端新增：

- 任务名称和说明搜索。
- 任务状态与截止状态筛选。
- 结果总数、分页和清空筛选。
- 每张任务卡显示截止时间、截止状态和学习进度。

后端始终使用当前登录学生身份过滤，学生不能通过参数查看其他学生任务。

### 4. 幂等与错误提示

- 已暂停任务再次批量暂停时会跳过，不会重复创建暂停事件。
- 不属于当前教师、已完成、分析中或状态不合适的任务会返回具体跳过原因。
- 空任务编号、非法状态和非法批量动作返回明确的 400 错误码。
- 批量操作最多 100 个任务，避免单次请求无限放大。

## 三、为什么这样改

本批没有做“批量提醒”。原因不是遗漏，而是当前通知模型不能可靠关联字符串格式的个性化任务编号。若现在临时拼接提醒，只能做成页面假状态，无法保证服务重启后仍存在，也无法防止重复通知。

因此边界是：

- 4A 先完成不需要数据库变更的搜索、分页、截止状态和批量暂停/恢复。
- 4B 再建立可持久化、可幂等的任务通知和定时提醒；该批必须先备份数据库并单独迁移。

## 四、页面上怎么看

教师登录后进入“个性化教学”，工作流说明下方会看到“任务运营”：

1. 输入任务名、学生名或任务编号并点击搜索图标。
2. 用两个下拉框筛选任务状态和截止状态。
3. 勾选任务后点击“批量暂停”或“批量恢复”。
4. 页面会显示变更数量和跳过数量。

学生登录后进入“个性化任务”：

1. 输入关键词查找任务。
2. 按学习状态或截止状态筛选。
3. 在任务卡中查看截止时间和进度。
4. 用底部分页按钮查看下一页。
