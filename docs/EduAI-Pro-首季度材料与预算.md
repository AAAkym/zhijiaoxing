# EduAI Pro 首季度项目材料与第一批预算

## 1. 编制说明

本材料用于项目第一次季度进度汇报（2026 年 6 月至 9 月）。内容依据项目季度报告、项目进展情况和后期工作计划整理。已完成事项、拟开展事项和预算安排分开表述，不将计划性工作写成既成成果。

## 2. 需求分析文档

### 3.1 项目背景

现有学习平台通常以统一内容和固定路径为主，难以持续识别学生的知识薄弱点、学习节奏和交互反馈。EduAI Pro 面向高校及职业教育场景，利用多智能体协同完成学情诊断、资源推荐、智能助教和任务调度，形成动态更新的自适应学习闭环。

### 3.2 用户角色

| 角色 | 核心需求 |
|---|---|
| 学生 | 查看学习路径，获得个性化资源、练习和答疑，跟踪学习进度 |
| 教师 | 查看班级学情，管理课程资源，了解薄弱知识点并进行教学干预 |
| 管理员 | 管理用户、课程、权限、系统配置和运行数据 |

### 3.3 功能需求

- 用户与权限：注册、登录、角色权限、个人资料和安全设置。
- 学习数据采集：记录做题正确率、学习时长、知识点错题、资源访问和交互反馈。
- 学情画像：根据多维行为数据计算知识点掌握度，形成可解释的动态画像。
- 多智能体协同：诊断智能体识别问题，推荐智能体选择资源，助教智能体提供解释，调度智能体编排任务。
- 自适应资源推荐：根据掌握度与学习状态调整内容难度和学习顺序。
- 学习空间：展示课程、任务、资源、进度和阶段反馈。
- 教学管理：教师维护课程与资源，查看班级分析和个体差异。
- 质量与安全：记录模型调用、审核生成内容、控制访问权限并保留操作日志。

### 3.4 非功能需求

- 可用性：基础登录、课程浏览和学习记录功能稳定可用。
- 性能：常规页面交互及时响应，模型调用具备超时与失败提示。
- 可扩展性：智能体、资源类型和课程模块可独立扩展。
- 安全性：最小权限、敏感配置隔离、输入校验和日志审计。
- 可解释性：推荐结果和画像变化能够追溯到学习行为依据。

### 3.5 首季度验收口径

首季度以“基础可运行、架构可扩展、数据链路打通”为验收重点：完成需求分析、总体架构和数据库初步设计，搭建前后端工程，完成登录、基础数据采集及首页/个人中心/学习空间等基础页面，完成小范围内部测试记录。

## 3. 系统架构设计文档

### 4.1 总体架构

系统采用 Web 前端、Flask 后端、关系型数据库、向量检索和多智能体编排相结合的分层架构。前端负责交互与可视化，后端负责权限、业务流程和数据持久化，智能体层负责诊断、推荐、助教和任务调度，知识库为检索增强生成提供专业资料。

### 4.2 分层设计

1. 表现层：React + Vite，提供首页、登录、个人中心、学习空间、教师和管理员工作台。
2. 接口层：Flask REST API，处理认证、课程、学习记录、推荐和管理请求。
3. 业务层：用户服务、课程服务、学习记录服务、画像服务、推荐服务和审核服务。
4. 智能体层：诊断智能体、资源推荐智能体、智能助教智能体、任务调度智能体及协同状态管理。
5. 数据层：关系型数据库保存业务数据，向量数据库保存知识片段，文件存储保存文档、视频等资源。
6. 基础设施层：模型服务、缓存、日志、监控和定时任务。

### 4.3 关键流程

学生产生学习行为后，后端写入行为记录并更新画像；诊断智能体分析薄弱知识点，推荐智能体检索并排序学习资源；任务调度智能体生成下一步学习任务；智能助教在学习过程中提供解释和反馈；新的学习结果再次回写画像，形成闭环。

### 4.4 风险与控制

- 智能体任务冲突：通过统一任务 ID、状态机和调度优先级控制。
- 模型输出不稳定：增加检索依据、规则校验、内容审核和失败兜底。
- 数据隐私风险：按角色限制访问，敏感配置使用环境变量，操作写入审计日志。
- 高并发延迟：采用异步任务、缓存和超时重试，避免请求长时间阻塞。

## 4. 数据库设计文档

### 5.1 核心实体

| 实体 | 关键字段 | 说明 |
|---|---|---|
| users | id, username, role, email, password_hash | 用户与角色 |
| courses | id, title, description, owner_id, status | 课程基本信息 |
| knowledge_points | id, course_id, name, parent_id | 课程知识点树 |
| learning_resources | id, course_id, type, title, uri, difficulty | 课件、习题、视频等资源 |
| learning_events | id, user_id, course_id, knowledge_point_id, event_type, score, duration | 学习行为事件 |
| student_profiles | id, user_id, mastery_json, preference_json, updated_at | 动态学情画像 |
| recommendations | id, user_id, resource_id, reason, score, status | 推荐结果及解释 |
| agent_tasks | id, workflow_id, agent_type, input_json, output_json, status | 智能体任务记录 |
| workflow_logs | id, workflow_id, event_type, payload_json, created_at | 协同流程审计 |

### 5.2 关系约束

- 一个用户可以拥有多个学习事件、推荐记录和智能体任务。
- 一个课程包含多个知识点和学习资源。
- 一个学习事件可关联一个知识点，画像由用户的多条事件聚合生成。
- 推荐记录引用资源并保存推荐原因，支持后续效果评估。
- 智能体任务通过 workflow_id 关联同一轮协同过程，workflow_logs 记录状态变化。

### 5.3 数据质量规则

- 用户名、角色和课程标题不能为空；密码只保存哈希值。
- 学习时长不得为负数，分数限制在定义范围内。
- 删除课程前检查资源、知识点和学习记录的关联关系。
- 画像更新保留更新时间和来源事件，便于解释与回溯。
