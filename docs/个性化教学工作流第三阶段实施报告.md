# 个性化教学工作流第三阶段实施报告

更新时间：2026-07-23

## 一、结论

第三阶段的产品闭环及原遗留的两条关键链路已经完成：教师发布资源时，系统会同步创建并绑定本轮 `Assessment`；学生完成这份精确检测后，FeedbackAgent、ProfileUpdateAgent 和 EvidenceReviewAgent 读取对应证据形成结论，高可信客观结论会更新画像白名单，并作为下一轮工作流的新画像输入。

本次完成度需要分两种口径理解：

- 第三阶段功能范围完成度：100%。发布、绑定检测、学习、精确证据、分析、画像白名单审核和下一轮工作流可以连通。
- 通知、逾期调度、全仓工程治理和真实账号试用已归入第四阶段，不能计入第三阶段完成度。

## 二、用户现在能看到什么

### 2.1 教师端

在“个性化教学”工作台中，资源生成并自动审核后会出现“发布与学习闭环”：

```text
审核通过的资源快照
→ 发布给当前学生
→ 查看任务状态和资源完成进度
→ 查看本轮真实评测来源与样本数
→ 查看五段因果链
→ 打开自动创建的下一轮工作流草稿
```

五段因果链为：

```text
发布前问题
→ 本轮策略
→ 学生真实表现
→ 画像审核结论
→ 下一轮教学动作
```

### 2.2 学生端

学生看板新增“个性化任务”：

- 查看教师发布的任务和完成条件。
- 开始任务并逐项完成学习资源。
- 前往现有练习或编程检测。
- 完成资源后触发本轮学习效果分析。
- 查看事实依据、证据可信度和下一轮策略。
- 证据不足时看到“证据不足”，不会被误判为学习失败。
- 练习和编程结果冲突时看到冲突提示，不会被强行归类为已掌握。

## 三、后端完成内容

新增三张第三阶段表：

1. `personalized_task_deliveries`：保存发布给学生的不可变任务快照。
2. `personalized_delivery_events`：只追加开始、进度、完成和检测绑定事件。
3. `personalized_learning_cycles`：保存本轮证据、Agent结论、周期画像和下一轮策略。

新增或补齐的主要接口：

- 教师发布、查看、暂停和恢复任务。
- 发布时把分层练习转换为现有 `Assessment`，测评编号写入任务完成规则。
- 学生任务列表、详情、开始、完成资源和提交检测。
- 教师或学生触发本轮效果分析。
- 查看工作流反馈和学习周期。
- 幂等获取自动创建的下一轮工作流。

权限会在发布时重新验证教师班级归属、学生成员关系和课程分配关系。学生接口始终使用当前登录用户，不接受客户端伪造的学生身份。

## 四、证据规则

系统现在明确区分两类证据：

| 证据类型 | 示例 | 能否直接支持掌握结论 |
| --- | --- | --- |
| 学习行为证据 | 看过资源、视频进度、任务完成 | 不能 |
| 能力评测证据 | 练习结果、错题、编程提交 | 可以 |

因此“看完两份资料”只能说明学生完成了任务，不能自动变成“学生掌握了知识”。

高可信周期结论要求至少两个评测来源、至少五个有效样本且可信度达到 80。练习与编程出现明显相反信号时，结果为 `evidence_conflict`，永久画像保持不变，下一轮安排短检测和过程复核。

前端提交检测时不能上传画像结论，只能引用后端已有记录编号。后端会逐条核验记录是否属于当前学生、课程、学习周期以及本任务绑定的 `Assessment`。即使是同一学生、同一课程，只要不是本任务测评，也会返回 403。

学生页面会显示本轮测评名称和编号，并直接打开该测评，不再让学生从课程练习列表中自行猜测。

## 五、Agent职责

- `ReviewAgent`：发布前再次检查资源完整性，外部 AI 不可用时用本地规则补齐。
- `FeedbackAgent`：根据本轮真实证据判断明显改善、部分改善、暂无改善、证据不足或证据冲突。
- `ProfileUpdateAgent`：生成周期画像变化建议和允许申请的白名单路径。
- `EvidenceReviewAgent`：检查来源、样本、冲突和可信度，决定结论可用于周期策略、永久画像白名单还是只保留观察。

永久画像只允许自动更新：

- `knowledge_base._verified_learning_cycles`：经过审核的课程、主题、结论、证据数量和测评编号。
- `error_patterns` 中来源为 `verified_learning_cycle` 的自动易错点。

认知风格、学习节奏、兴趣、目标、可用时间和互动偏好不会被一次检测覆盖。画像更新后，下一轮工作流会使用更新后的快照，而不是旧画像。

下一轮草稿不是简单复制上一轮。系统会根据结果选择进阶、巩固、基础补偿、短检测或冲突复核策略。

## 六、中断和重复请求

- 重复发布不会创建第二个学生任务。
- 重复完成资源不会重复累计进度。
- 重复分析返回同一个学习周期。
- 如果证据已经保存但下一轮工作流创建中断，周期进入 `NEEDS_ATTENTION`，页面得到可重试提示。
- 再次请求会从保存的证据继续，只创建一个周期和一个下一轮草稿。

“不能失败”在产品中实现为：外部服务异常或流程中断时，不丢数据、不制造重复记录，并给用户明确的恢复路径，而不是声称网络和外部 AI 永远不会异常。
