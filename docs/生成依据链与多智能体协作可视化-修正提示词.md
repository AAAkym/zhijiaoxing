## 1. 为什么你会被这个假象误导（重要认知）

`backend/src/main.py` 第 1059~1072 行有一个**通配 SPA 兜底路由**：

```python
@app.route('/', defaults={'path': ''})
@app.route('/<path:path>')
def serve(path):
    static_folder_path = app.static_folder
    if static_folder_path is None:
        return 'Static folder not configured', 404
    if path != '' and os.path.exists(os.path.join(static_folder_path, path)):
        return send_from_directory(static_folder_path, path)
    index_path = os.path.join(static_folder_path, 'index.html')
    if os.path.exists(index_path):
        return send_from_directory(static_folder_path, 'index.html')
    return 'index.html not found', 404
```

它把**所有未匹配的路径**（包括 `/api/*`）都返回 `index.html`，且 **HTTP 状态码是 200**。

后果：**"路由不存在"与"功能正常"在 HTTP 层面完全无法区分**。任何后端没重启、路由没注册、blueprint 没挂载的问题，都会伪装成"接口返回了 HTML"。

**这正是任务书第 8 节把"全量回归"列为最后一步却仍出事的原因**：没有人真正验证过新接口在运行态存在。

### 步骤 2：验证路由真的注册了（**不允许跳过**）

**不要用浏览器或前端界面验证。** 必须用下面的显式契约检查：

```powershell
foreach ($u in @("/api/classes/1/learning-groups", "/api/classes/1/stats")) {
  try {
    $r = Invoke-WebRequest -Uri "http://localhost:5000$u" -UseBasicParsing -TimeoutSec 10 -ErrorAction Stop
    $isHtml = $r.Content.TrimStart().StartsWith("<!DOCTYPE") -or $r.Content.TrimStart().StartsWith("<html")
    Write-Output "$u => $($r.StatusCode) | $($r.Headers['Content-Type']) | HTML=$isHtml"
  } catch {
    $resp = $_.Exception.Response
    Write-Output "$u => $([int]$resp.StatusCode) | $($resp.ContentType)"
  }
}
```

**通过标准：新接口必须返回 `application/json`（未登录时 401 JSON 也算通过——那证明路由已注册，只是鉴权拦截）。**

**失败特征：返回 `text/html` 或 `HTML=True`。** 见到这个，说明路由仍未注册，回到步骤 1，不要继续后面的步骤。
