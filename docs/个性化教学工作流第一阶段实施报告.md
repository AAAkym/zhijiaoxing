## 二、现在产品能做什么

教师进入“个性化教学”后，可以完成以下流程：

```text
选择课程、班级和学生
→ AI结合课程上下文拆分知识点
→ 教师确认、删除或补充知识点
→ 查看练习、错题、编程、互动和画像证据
→ 选择本次允许使用的证据
→ 查看“证据 → 教学动作 → 资源”的方案
→ 教师补充生成要求并确认
→ 查看六阶段多 Agent 真实执行记录
→ ReviewAgent 自动审核并最多修复两轮
→ 预览最终资源
→ 教师主动保存草稿或提交 AI 审核
```

没有学生画像时，系统不会虚构个性化特征，而是明确显示“通用方案”。教师可以主动选用已有练习、错题等事实，这些事实只影响本次生成，不会被描述成长期学生特征，也不会写回画像。

## 三、已完成内容

| 模块 | 已实现结果 |
| --- | --- |
| 独立教师入口 | 教师菜单新增“个性化教学”，原普通内容生成保留 |
| 三级选择与权限 | 课程 → 已分配班级 → 班内学生；后端再次校验教师归属、成员关系和课程关系 |
| 知识点准备 | 优先由 AI 结合课程上下文生成，教师可勾选、取消、编辑式补充 |
| 学习证据 | 读取画像、练习、错题、编程、视频和互动数据；缺数据时明确显示证据不足 |
| 方案生成 | 输出学习顺序、资源类型及“证据 → 动作 → 资源”映射；教师勾选的事实会真实改变方案 |
| Agent 过程 | 同一 tracking_id 轮询真实状态，展示六阶段、资源 Agent、执行摘要和进度 |
| 不可用保障 | 外部 AI/RAG 不可用时明确提示并使用本地规则补齐可编辑资源；知识检索显示“跳过”而不是伪报成功 |
| ReviewAgent | 检查固定结构和语义一致性，最多自动修复两轮；结构必须完整、语义达到 80 分才允许提交 |
| 外部资源 | 校验可访问性；不可用时保留本地内容并显示原因，不伪造“可用”状态 |
| 写入控制 | 预览、诊断、计划、生成都不写数据库；只有教师点击“保存为草稿”或“提交AI审核”才执行原有新增流程 |
| 防重复 | 同一工作流重复生成、重复保存和重复提交均复用已有结果，不产生重复记录 |
| 状态边界 | 页面明确提示工作流暂存在内存中，服务器重启会丢失未保存流程 |

## 六、尚未完成的内容

以下内容属于完整产品的第二至第四阶段，本次没有实现，也不应被描述成已经完成：

1. 工作流持久化：服务器重启后恢复、完整事件历史、暂停后继续和长期审计。
2. 发布学生任务：指定截止时间、完成要求、提醒并准确下发给目标学生。
3. 学生学习页面：阅读、练习、编程实践和任务进度统一进入同一工作流。
4. 学后检测闭环：使用等价题评估效果、判断达标、自动进入补偿学习。
5. 画像与路径回写：经规则验证后更新画像证据、可信度和下一轮学习路径。
6. 生产稳定性：通知、搜索、筛选、批量操作、运行监控、性能治理和真实用户试用。

这些功能需要可靠保存工作流、任务和评测状态。继续坚持“数据库零改动”无法把它们做成生产级能力，因此进入第二阶段前必须单独评审数据模型并获得数据库变更确认。
