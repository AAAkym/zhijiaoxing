# 个性化教学工作流第二阶段实施报告

更新时间：2026-07-23

## 先说结论

第二阶段“工作流持久化与可恢复”已经完成并接入现有教师端。

现在系统可以把一次个性化教学流程保存成一条工作流记录，记录方案、生成结果、审核结果和状态事件。教师刷新页面或服务重启后，可以从“最近工作流”点击“继续”，恢复原来的主题、知识点、方案和时间线。

本阶段没有使用旧的 Alembic 全量迁移。旧迁移文件包含删除历史业务表的操作，本次没有执行它。

## 完成内容

### 1. 数据和升级

- 新增 `personalized_workflows`：保存工作流对象、教学范围、方案、生成结果、审核结果和当前状态。
- 新增 `personalized_workflow_events`：保存创建、修订、开始生成、审核、暂停、恢复等事件。
- 新增安全升级器 `backend/scripts/migrate_personalized_workflow_phase2.py`。
- 升级器默认只检查；只有显式传入 `--apply` 才会修改数据库。
- 支持 `--rollback --apply`，只回滚本阶段新增的两张表。
- 真实开发库已完成升级，备份文件为：
  `backend/backups/dev.before_phase2_20260723_031334_053299.db`

升级后核对结果：

- 原有 61 张表逐表行数与备份完全一致。
- 新增两张表当前均为 0 条，不会凭空生成业务记录。
- SQLite `integrity_check` 升级前后均为 `ok`。
- 升级前后外键悬挂记录逐条相同，共 66 条，属于历史数据问题，不是本次新增。

### 2. 后端工作流能力

- 方案接口支持创建和修订同一条工作流，不会因为修改证据重复创建记录。
- 生成使用数据库条件更新抢占，重复请求只允许一个请求进入生成状态。
- 生成结果写入工作流快照，但不写入原有课程业务内容；点击“保存为草稿”或“提交AI审核”时仍走原有明确写入动作。
- 增加工作流列表、详情、暂停和恢复接口。
- 详情接口会把长时间停留在生成中的工作流恢复为“需要继续处理”。
- 所有读取和修改都校验当前教师身份，其他教师无法读取工作流详情或列表。
- 生成事件使用每次独立 `tracking_id`，中断后重试不会触发事件唯一键冲突。
- 暂停会记录暂停前状态，恢复时回到暂停前状态，而不是强行回到等待确认。

### 3. 前端工作台

- 工作台加载最近 10 条本人工作流。
- 点击“继续”会先读取完整详情，再恢复主题、课程、班级、学生、知识点、资源类型、方案和生成结果。
- 新增“工作流记录”时间线，展示状态变化和发生时间。
- 增加暂停/恢复按钮，生成中禁止重复提交。
- 服务重启提示改为“工作流记录会恢复，课程业务内容仍需明确保存”，避免把两类写入混为一谈。

## 给新手的使用方式

1. 启动前端后进入教师端。
2. 点击“个性化教学”。
3. 在“最近工作流”中点击“继续”。
4. 页面会恢复上次方案，并在底部“工作流记录”显示过程。
5. 如果状态显示“需要继续处理”，先查看提示，再点击恢复或重新生成。
