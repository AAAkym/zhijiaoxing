# EduAI Pro 系统架构设计文档

## 1. 设计目标

构建可扩展、可解释、可持续迭代的多智能体自适应学习平台，打通“学习行为采集—学情诊断—资源推荐—任务执行—结果反馈”链路。

## 2. 总体架构

系统采用 Web 前端、Flask 后端、关系型数据库、向量检索和多智能体编排相结合的分层架构。前端负责交互与可视化，后端负责权限、业务流程和数据持久化，智能体层负责诊断、推荐、助教和任务调度，知识库为检索增强生成提供专业资料。

## 3. 分层设计

1. 表现层：React + Vite，提供首页、登录、个人中心、学习空间、教师和管理员工作台。
2. 接口层：Flask REST API，处理认证、课程、学习记录、推荐和管理请求。
3. 业务层：用户服务、课程服务、学习记录服务、画像服务、推荐服务和审核服务。
4. 智能体层：诊断智能体、资源推荐智能体、智能助教智能体、任务调度智能体及协同状态管理。
5. 数据层：关系型数据库保存业务数据，向量数据库保存知识片段，文件存储保存文档和视频资源。
6. 基础设施层：模型服务、缓存、日志、监控和定时任务。

## 4. 核心协同流程

学生产生学习行为后，后端写入行为记录并更新画像；诊断智能体分析薄弱知识点，推荐智能体检索并排序学习资源；任务调度智能体生成下一步学习任务；智能助教在学习过程中提供解释和反馈；新的学习结果再次回写画像，形成闭环。

## 5. 风险与控制

- 智能体任务冲突：使用统一任务 ID、状态机和调度优先级控制。
- 模型输出不稳定：增加检索依据、规则校验、内容审核和失败兜底。
- 数据隐私风险：按角色限制访问，敏感配置使用环境变量，操作写入审计日志。
- 高并发延迟：采用异步任务、缓存和超时重试，避免请求长时间阻塞。
